# GUI 拖动与合成性能

窗口拖动使用输入事件的原始双轴像素位移。标题栏在左键按下时获取拖动状态，保持至释放或窗口销毁；窗口位置和鼠标位置使用同一份位移。窗口 X 坐标无需按 4 像素对齐：按报告舍入会丢弃连续的 ±1 像素移动，并让左右移动出现不对称。USB 高频小位移报告尤其容易触发这一问题。

## 合成路径

`apps/gui/sheet.h` 定义独立的图层接口，`sheet.c` 不依赖 GUI RPC 或输入接口。像素归属仍使用稳定的图层指针，显示仍遵循实际 stride 和 RGB 位序。

移动图层时，位置不变立即返回；位置变化后，新区域完整合成一次，旧区域仅合成新区域没有覆盖的部分。矩形相交时，旧位置露出的部分至多分成四个不重叠条带；不相交时重绘两个独立矩形。透明图层的新区域同样完整合成，以恢复透明像素下方的窗口。

旧实现对旧、新两个矩形分别完整重建归属并写屏，重复处理相交区域。旧矩形包含露出的背景时，未归属像素还会让算法继续遍历下方各层，即使这些层的大部分已经被覆盖。分离露出条带既减少重复写屏，也减少这些无效扫描。鼠标按钮事件产生的零位移不再触发两次光标合成。

客户端绘图缓冲复制到 GUI 持有的已提交画面仍然必要：它保证遮挡恢复时不读取客户端正在绘制的半帧。`window_present` 的同步应答与 `window_refresh` 的异步 damage 合并语义保持一致。普通内容刷新没有改变，本次没有测得这一场景的稳定加速。应用端渲染、RPC、调度竞争和真实 framebuffer 写入成本仍须在目标机器单独测量。

## 可复现基准

```sh
# baseline 指定修改前的提交；默认 HEAD 适用于尚未提交的工作区修改。
taskset -c 0 python3 scripts/compare-gui.py \
  --baseline f963fe6043d415d50066b0191e9e47e1836979a8 --runs 7
```

脚本分别编译指定提交与工作区的实际 `sheet.c`，使用相同的独立测试驱动，不复制合成算法。旧版仅将 `gui.h` 包含替换为抽出的同一份图层声明。可用 `CC` 选择宿主 C 编译器；临时源码和可执行文件在结束后删除。

基准使用 1024×768 RAM framebuffer、640×400 被拖动窗口、16×19 透明光标，分别测试下方有 0 和 32 个被覆盖窗口的场景。每项执行 400 次；前后版本交替执行 7 轮，报告每操作耗时的中位数。移动场景在相邻像素间往返，包含水平、垂直、对角和光标移动；普通刷新为整窗口刷新。零位移返回时间接近计时下限，显示为 `no-op`，不计算夸大的倍数。

一次固定 CPU 0 的测量结果如下：Intel Core Ultra 7 270K Plus，Linux/Hyper-V 环境，GCC 15.2.0，`-O2 -std=gnu17`。单位为 µs/操作。

| 被覆盖窗口数 | 场景 | 修改前 | 修改后 | 加速比 |
| --- | --- | ---: | ---: | ---: |
| 0 | 水平移动 | 441.691 | 201.989 | 2.19× |
| 0 | 垂直移动 | 437.229 | 193.008 | 2.27× |
| 0 | 对角移动 | 441.576 | 202.281 | 2.18× |
| 0 | 光标移动 | 1.817 | 1.100 | 1.65× |
| 0 | 普通内容刷新 | 84.019 | 83.399 | 1.01× |
| 32 | 水平移动 | 1337.216 | 203.092 | 6.58× |
| 32 | 垂直移动 | 1333.066 | 192.249 | 6.93× |
| 32 | 对角移动 | 1328.024 | 201.744 | 6.58× |
| 32 | 光标移动 | 1.791 | 1.082 | 1.66× |
| 32 | 普通内容刷新 | 82.733 | 82.858 | 1.00× |

零位移原来约 381 µs，现在直接返回。这些数据证明合成算法的 CPU 工作量改善，不代表真实机器或 SDL/Vulkan/OpenGL 应用的端到端 FPS。宿主 RAM、memcpy 和执行环境不同于 Plant OS 的用户运行库及显存，不能直接将上述耗时倒数当成应用帧率。

## 正确性与输入回归

每轮基准均使用独立的逐像素、从后向前参考渲染器检查 framebuffer 和像素归属。确定性随机序列覆盖移动、远距离跳转、屏外裁剪、透明/不透明图层、层级变化、隐藏及销毁；分别检查 RGB/BGR 和带填充的 pitch，并确认行填充没有被覆盖。计时后的完整场景也进行像素校验。

可用宿主检查器验证同一源码：

```sh
cc -O1 -g -std=gnu17 -fsanitize=address,undefined -fno-omit-frame-pointer \
  -Iapps/gui apps/gui/sheet.c scripts/tests/gui-compositor.c \
  -o /tmp/plant-gui-sanitize
/tmp/plant-gui-sanitize
```

系统内回归通过 init.mst 启动程序，仅通过 QMP 发送真实相对位移和按钮事件。`--mouse` 和 `--usb` 在测试窗口标题栏按住左键，依次发送 8 个 +1 X、−1 X、+1 Y、−1 Y 报告，每段比较移动后窗口边框的实际像素，然后检查客户区按钮、滚轮和位置事件。截图保存为 `mouse-drag-*.ppm`。原先的逐报告舍入无法通过横向检查。

本次实际通过以下完整构建、LiveCD 打包和 QEMU TCG 冷启动回归（CPU `max`，4 核）：

```sh
python3 scripts/test-x86_64.py --mouse --memory 3072 --timeout 180
python3 scripts/test-x86_64.py --usb --memory 3072 --timeout 240
python3 scripts/test-x86_64.py --arch i386 --mouse --memory 512 --timeout 180
```

USB 专项还覆盖 USB 键盘、终端像素、热插拔及存储校验。测试脚本恢复正常启动配置并重新打包镜像。真实 USB 鼠标及物理显示器上的最终拖动体验尚需在目标机器确认。
